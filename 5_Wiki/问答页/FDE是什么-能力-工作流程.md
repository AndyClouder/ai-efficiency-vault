# FDE 是什么、提供什么能力、怎么工作

> 问答回灌页。原问题："FDE是什么，提供的能力是什么，工作流程是什么样的"

## 当前综合结论

FDE（Forward Deployed Engineer / Field Deployment Engineer，前沿部署工程师）是 AI 时代催生的交付角色，介于咨询与外包之间却本质不同。它派最贵的工程师到最不标准化的客户现场，把"连客户自己都说不清"的问题定义出来，再造出方案，最后把现场经验反馈回自己的产品团队形成复利飞轮。

三种角色共享同一母问题——"客户需要的东西，我手头没有现成的"——但对"为什么没有"的前提假设不同：咨询假设"知识可被传授"，外包假设"知识可写进文档"，FDE 假设"知识只能在行动中涌现"。FDE 的核心输出是**代码 + 认知 + 产品洞察**三位一体，核心能力是**双重翻译能力**（业务↔技术、现场↔产品）。

价值本质：**咨询赚认知的钱，外包赚效率的钱，FDE 赚复利的钱。**

## FDE 是什么

| 角色 | 前提假设 | 核心输出 | 知识模型 |
|------|---------|---------|---------|
| **咨询** | 客户有需求但不知道需求长什么样 | 认知（PPT/框架/路线图） | 知识转移（可被传授） |
| **外包** | 客户知道需求但没时间/能力做 | 产能（代码/系统） | 知识执行（可写进文档） |
| **FDE** | 客户连需求都说不清，问题在认知之外 | **转化**（代码+认知+产品洞察） | **知识涌现**（只在行动中产生） |

（[[FDE模式]]，源自 [[2026-06-02-FDE-vs-咨询-vs-外包]]）

## 提供的能力

核心能力是**双重翻译能力**（[[FDE模式]]）：

1. **业务↔技术翻译**：把客户模糊的业务感知翻译成可执行的技术方案
2. **现场↔产品翻译**：把现场经验翻译成产品需求，反馈给自己的产品团队

**分水岭标尺（三维度）：**
- 价值交付物：代码 + 产品改进提案 + 客户持续在用（而非 PPT 或交接文档）
- 互动方向：**反馈给自己的产品团队**（不是客户）
- 复利效应：有飞轮——一个客户的经验沉淀进产品，所有客户受益

> 关键警示（[[FDE模式]]）："没有反馈闭环的 FDE 就是外包；没有落地承诺的 FDE 就是咨询。"

## 工作流程

库内来源用「银行 AI 信贷审批」场景做了完整演示（[[2026-06-02-FDE-vs-咨询-vs-外包]]）。FDE 与咨询/外包的流程对比：

```
咨询：  访谈→现状/目标流程图→差距分析→80页PPT→建议路线图→走人
外包：  等需求文档→按文档写代码→系统上线→交付→撤
FDE：  坐到客户旁边观察→搭粗糙原型跑历史数据→发现模型判错→调整特征工程→把场景需求反馈给产品团队
```

**FDE 的标准闭环（4 步）：**

1. **现场观察**：坐在客户业务人员旁边，花一周观察他们真实的工作方式（很多规则"写在纸上贴在工位上"，不在系统里）
2. **快速原型验证**：用客户历史数据搭粗糙原型跑一遍，暴露问题（如某类贷款拒绝率从 30% 飙到 70%，但人工审核 60% 是过的——模型判错了）
3. **迭代修正**：调整特征工程等，重新跑直到效果好
4. **反馈产品团队**：把现场发现的通用场景需求写成提案反馈给总部产品团队 → 沉淀成可配置产品模块 → 同行业其他客户直接复用

> 原文案例结尾：那个派 FDE 的公司，花三个月把"小微企业信贷"做成产品模块，后来同行业三家银行都买了（[[2026-06-02-FDE-vs-咨询-vs-外包]]）。

## ⚔️ 矛盾与张力

### AI 时代边界模糊下的身份风险（未解决）
AI 让"探索"与"执行"切换成本急剧降低——一个 FDE 用 Claude Code 半天搭原型，能包揽过去三角色接力的事。**但**："如果你以'外包'心态进客户现场，AI 不会把你变成 FDE，你只是比原来写代码更快的外包。" 分水岭不是"会不会用 AI"，而是"你把现场经验带回了哪里"（[[AI对咨询外包行业的冲击]]、[[2026-06-02-FDE-vs-咨询-vs-外包]]）。—— 状态：**未解决**（需个人/组织层面主动构建反馈闭环）
