# 售前 PPT 章节结构库

> 4 大章节范式 + 12 种通用页面类型。按客户特点和受众选范式,按内容选页面类型组合。
>
> 来源:从高力国际售前 PPT 等实战项目提炼。

---

## 一、4 大章节范式

### 范式 1:标准售前(最常用)

**适用**:4-6 个业务场景的中大型方案,客户有明确的多场景需求。
**页数**:23-30 页
**受众**:通用(可适配决策层/业务+IT)

```
开篇(2 页)
├── 封面
└── 目录

第一章 客户理解与价值主张(4 页)
├── 章节封面
├── 客户认知(定位 + 业务特点 + 价值主张)
├── N 大业务痛点(2×2 矩阵,每痛点关联 AI 切入点)
└── 整体价值闭环(横向流程图,客户原话优先)

第二章 总体方案架构(3 页)
├── 章节封面
├── 总体架构图(分层:集成层/场景层/平台底座)
└── 产品矩阵映射(自有产品 → 客户场景)

第三章 场景方案(N 个场景 × 2 页)
├── 章节封面
├── 场景1:痛点 + 流程
├── 场景1:能力 + 价值
├── 场景2:痛点 + 流程
├── 场景2:能力 + 价值
└── ...(每场景 2 页)

第四章 价值、实施与保障(4 页)
├── 章节封面
├── 商业价值矩阵(2×2,每场景量化指标)
├── 实施路径(3 阶段时间线)
└── 我方保障(四列:能力底座/交付经验/安全合规/生态合作)

封底(1 页)
└── 致谢 + 联系方式
```

**核心信息写法**:每章首句即结论。如"四大场景串联成完整业务闭环"、"以 FarAgent 平台为统一底座,向上承载四大场景"。

---

### 范式 2:痛点驱动

**适用**:竞标/强竞争场景,客户已明确痛点,需要强力诊断式叙事。
**页数**:20-25 页
**受众**:决策层为主

```
开篇(2 页):封面 + 目录
第一章 行业洞察(3-4 页):趋势 + 政策 + 市场空间 + 竞争格局
第二章 痛点诊断(4-5 页):客户现状 → N 大痛点深度拆解(每痛点配数据)
第三章 解决方案(5-6 页):总体方案 + 差异化能力 + 核心场景
第四章 案例验证(3-4 页):标杆案例 + 量化成果 + 客户证言
第五章 实施路径(2-3 页):分阶段 + 时间线 + 保障
封底(1 页)
```

**特点**:诊断犀利,案例为王。每页要有数据支撑。

---

### 范式 3:产品演示

**适用**:产品推介,客户想看产品能力。
**页数**:18-22 页
**受众**:业务+IT 为多

```
开篇(2 页)
第一章 产品概览(3 页):定位 + 1+4+X 矩阵 + 核心优势
第二章 核心能力(4-5 页):逐个能力展开(功能 + 截图 + 价值)
第三章 场景演示(5-6 页):典型场景的操作流 + 效果
第四章 技术架构(2-3 页):架构图 + 安全 + 集成
第五章 合作模式(2-3 页):部署方式 + 服务体系 + 报价框架
封底(1 页)
```

**特点**:重产品展示,要有界面/截图/演示流。

---

### 范式 4:高管简报

**适用**:30 分钟以内的高管汇报,只讲核心。
**页数**:10-15 页
**受众**:决策层(高管)

```
封面(1 页)
执行摘要(1 页):一句话价值主张 + 3 个核心数字
3 大价值(3 页):每页一个价值点(大数字 + 一句话)
1 个标杆场景(2-3 页):最能打动高管的场景展开
合作建议(1-2 页):下一步行动 + 投资概算
封底(1 页)
```

**特点**:极简,每页只有一个核心信息。大字号,多留白。不堆细节。

## 二、12 种通用页面类型库

> 不管选哪个范式,页面由这些类型组合。每种给布局描述。

| 页面类型 | 布局 | 适用 | core message 写法 |
|---------|------|------|------------------|
| **封面** | 单列居中 + 左侧色块 | 第一页 | 项目名 + 副标 + 公司 |
| **目录** | 四列卡片(章节) | 第二页 | "N 章节构成完整方案叙事" |
| **章节封面** | 深蓝渐变 + 巨型章节号 | 每章首页 | 章节号 + 章节标题 + 副标 |
| **痛点矩阵** | 2×2 卡片 | 痛点页 | "N 大痛点 — 客户的 AI 切入点" |
| **价值闭环** | 横向流程图 + 闭环回流 | 核心叙事页 | "从 X 到 Y 的完整闭环" |
| **架构图** | 三层分层(集成/场景/底座) | 方案页 | "X 底座 × N 场景 × 系统集成" |
| **场景方案** | 上痛点 + 下流程 / 左能力 + 右价值 | 场景展开 | "场景名 — 核心价值主张" |
| **决策链/关系图** | 中心辐射 | 复杂关系页 | "统一视图 — 核心差异化" |
| **价值矩阵** | 2×2 量化卡片 | 价值页 | "N 维度的效率·成本·收入提升" |
| **实施路径** | 三阶段时间线/瀑布 | 实施页 | "试点 → 扩展 → 闭环" |
| **保障能力** | 四列卡片 | 信任页 | "为什么是我们 — N 大保障" |
| **封底** | 单列居中 + 渐变 | 末页 | slogan + 联系方式 |

## 三、章节规划检查清单

产出大纲后自检:

- [ ] **封面 + 目录 + 封底齐全**(任何范式都要有头尾)
- [ ] **每章有章节封面**(anchoring,让读者知道到哪了)
- [ ] **至少一个价值闭环页**(决策层最爱的叙事,优先用客户原话)
- [ ] **痛点页能关联 AI 切入点**(不关联的痛点不放进 PPT)
- [ ] **每个场景至少 2 页**(痛点流程 + 能力价值,不能只讲一面)
- [ ] **价值页有量化指标**(查 value-estimation.md,标"预估")
- [ ] **实施页分阶段**(决策层要看到路径,不是一次性)
- [ ] **页数符合范式区间**(标准 23-30 / 痛点 20-25 / 产品 18-22 / 高管 10-15)

## 四、page_rhythm 怎么标(配合 ppt-master)

| 页面类型 | rhythm | 理由 |
|---------|--------|------|
| 封面/目录/章节封面/封底 | `anchor` | 结构性页面,版式固定 |
| 痛点矩阵/架构图/场景方案/价值矩阵 | `dense` | 信息密集,卡片网格 |
| 价值闭环/单句slogan页 | `breathing` | 低密度强调,留白多 |

**原则**:23 页方案通常 4-5 个 anchor(封面+目录+各章封面+封底)、1-3 个 breathing(闭环页等)、其余 dense。
