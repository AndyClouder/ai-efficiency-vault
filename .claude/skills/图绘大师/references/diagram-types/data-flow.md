# 类型：data-flow(数据流图 / 管道)

> 源 → 处理 → 汇，数据用粗箭头表示流动。用于数据流向、ETL 管道、信息流。与 flowchart 的区别：data-flow 强调**数据本身**(带数据类型/格式标注)，flowchart 强调**动作步骤**。

## 1. 构图骨架

横向管道(最常见)：
```
[数据源] ⇒ [采集] ⇒ [清洗] ⇒ [转换] ⇒ [存储] ⇒ [消费]
  MySQL     Kafka    Spark    Flink    HDFS     BI
```

- **节点**：阶段框(数据源/处理/存储/消费)，统一形状
- **数据流箭头**：**粗箭头**(3-4px)，明显比 flowchart 的步骤箭头粗，强调"数据在流"
- **数据标签**：箭头上方标注数据格式/内容("JSON 日志" / "清洗后事件" / "聚合指标")

## 2. 节点分类(用颜色/图标区分)

| 类型 | 典型 | 配色建议 |
|---|---|---|
| 数据源 | DB / API / 日志文件 / IoT | 蓝 |
| 处理 | Kafka / Spark / Flink / 函数 | 紫 |
| 存储 | HDFS / S3 / 数仓 | 绿 |
| 消费 | BI / API / 机器学习 | 橙 |

> 颜色都在 spec_lock 色系内；通过明度/色相区分类型。

## 3. 数据流箭头规则

**粗箭头 + 数据标签**：
```xml
<line x1="300" y1="360" x2="500" y2="360" stroke="#1E3A5F" stroke-width="4" marker-end="url(#arrowHead)"/>
<text x="400" y="345" text-anchor="middle" font-size="12" font-weight="600" fill="#1E3A5F">原始日志 · JSON</text>
```

**分流**(一 source → 多 sink)：从一个节点引出多条粗箭头到不同目的地，每条标数据子集。

**合流**(多 source → 一处理)：多条粗箭头汇入一个节点。

## 4. 默认画布

| 阶段数 | 画布 |
|---|---|
| 3-5 阶段 | 1280×720 |
| 6-7 阶段 | 1920×720(横长条) |
| 纵向(垂直管道) | 720×1280 |

## 6. 红线

- ❌ 不画无数据标签的流(读者不知道流的是什么)
- ❌ 数据流箭头太细(与 flowchart 步骤箭头混淆)
- ❌ 节点类型不分(数据源和处理混在一色)
- ✅ 每段流标明数据格式/内容
- ✅ 主流向单一(左→右 或 上→下)
