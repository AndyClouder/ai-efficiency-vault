# 类型：sequence(时序图 / 交互序列)

> 顶部角色(参与方)列 + 纵向生命线 + 横向交互箭头。用于请求-响应、API 调用、协议交互、多角色对话。与 flowchart 的区别：sequence 强调**谁和谁交互 + 时间先后**，flowchart 强调**步骤流转**。

## 1. 构图骨架

```
[客户端]          [网关]          [服务]          [数据库]
   │                │                │                │
   │──── ①请求 ────→│                │                │
   │                │──── ②转发 ────→│                │
   │                │                │──── ③查询 ────→│
   │                │                │←── ④返回 ──────│
   │                │←── ⑤响应 ──────│                │
   │←── ⑥数据 ──────│                │                │
```

- **角色头部**：顶部 2-5 个角色卡片(方框 + 名字)，水平等距
- **生命线**：每个角色下方一条纵向虚线 `<line stroke-dasharray="4 4">`，贯穿到底
- **交互箭头**：横向实线箭头，连接两条生命线，**带编号 + 动作标签**
- **时间方向**：从上到下 = 时间推进；交互按发生顺序自上而下排列

## 2. 角色规则

| 字段 | 内容 |
|---|---|
| 角色名 | 客户端/网关/服务/数据库 等，≤4 字 |
| 角色类型 | 可加副标题(如"Browser" / "Kong") |

角色头部用与 architecture 节点类似的卡片画法，但更窄(约 160-200px 宽)。

## 3. 交互箭头规则

**实线 + 实心箭头** = 请求/调用：
```xml
<line x1="220" y1="250" x2="900" y2="250" stroke="#1E3A5F" stroke-width="2.5" marker-end="url(#arrowHead)"/>
<rect x="460" y="234" width="240" height="26" rx="11" fill="#FFFFFF" stroke="#1E3A5F" stroke-width="1"/>
<text x="580" y="251" text-anchor="middle" font-size="13" font-weight="700" fill="#1E3A5F">① 登录请求 · POST /login</text>
```

**虚线 + 实心箭头** = 响应/返回：
```xml
<line x1="900" y1="290" x2="220" y2="290" stroke="#10B981" stroke-width="2.5" stroke-dasharray="6 4" marker-end="url(#arrowHead)"/>
```

> **每条交互必须有编号 + 动作标签**。编号表顺序，动作标签说清"这次交互做了什么"(如"② 转发请求"、"④ 返回 JWT")。禁止画无标签的交互线。

## 4. 自调用与异步

- **自调用**：箭头从生命线出发又回到自己(小弧或小折线)
- **异步消息**：可用不同颜色或标注"(async)"

## 5. 默认画布

1280×720(16:9)。3-4 个角色最舒适；5 个角色时角色卡变窄；超过 5 个角色建议拆图或只画关键链路。

## 6. 参考模板

`templates/charts/client_server_flow.svg` —— 左侧客户端组 + 右侧服务端组 + 中间编号交互，结构最完整。取其角色分组 + 编号药丸标签 + 双向箭头的画法。

## 7. 红线

- ❌ 不画无编号无标签的交互(读者不知道每步是什么)
- ❌ 交互箭头不按时间顺序乱排(必须自上而下)
- ❌ 生命线断开或不贯穿
- ✅ 请求与响应用不同线型(实线 vs 虚线)或不同颜色区分
