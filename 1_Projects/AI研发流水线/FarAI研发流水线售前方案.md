## 二、客户理解(决策层视角)

> 本场景"客户"= 科技公司的研发组织(潜在买方)。三层认知如下。

### 客户定位

**正在或即将用 AI 武装研发团队的中大型科技公司研发组织。**

特征:已经采购或自研了 AI 编码工具(如 Copilot/Cursor/自研 Agent),一线工程师个人层面有体感提效,但研发负责人和 CTO 层面"感受不到组织级提速"。典型画像:几百到几千研发人员、多产品线、有 DevOps 基础、面临"AI 工具买了但效能说不清"的焦虑。

### 业务特点(影响方案设计的 5 个特征)

1. **协作链路长** —— 软件交付不是一个人的事,需求→设计→编码→测试→发布→运营是协作链。个人变快,链路不变,组织不变快。
2. **AI 工具已下沉到个人** —— 工程师普遍用 AI 读代码、写代码、补测试,但停留在"个人工具"层面,没有变成"组织能力"。
3. **测试与环境是瓶颈** —— AI 写完代码,组织不敢合并/重构/发布,因为缺乏可自动验证的安全网。
4. **知识散落** —— 需求/设计/代码/测试/契约/规则分散,Agent 拿不到准确上下文,容易找错信息、误解概念。
5. **治理焦虑** —— 既怕 AI 乱跑出事(质量/安全/合规),又怕管太死把速度优势抵消。

### 痛点清单(每个痛点关联 AI 切入点)

| # | 痛点(客户视角原话化) | AI 切入点(FarAI 怎么解) |
|---|----------------------|--------------------------|
| **P1** | "每个人都在用 AI,但版本还是按原节奏发,组织没变快" | 把个人提效转化为小队/产品线/组织级系统提效——四闭环 + 三层流动 |
| **P2** | "AI 写的代码我们不敢合、不敢重构,怕出事" | Harness 先行:fullcheck + CLI E2E + 自动化测试安全网,让 AI 改完即可验证 |
| **P3** | "Agent 拿不到准确上下文,老找错代码、误解业务" | 本体网络 + 知识联通底座,让 Agent 沿语义/依赖/契约找上下文 |
| **P4** | "AI 工具买了一堆,效能提升说不清,Token 钱花得没底" | AI FinOps + 效能度量,把"用了多少 AI"升级为"AI 带来什么收益" |

**铁律自检**:4 个痛点都能关联到 FarAI 能力,不开空头支票。✅

## 三、产品定位(FarAI 研发流水线)

### 一句话定位

> **FarAI 研发流水线** —— 让"个人用 AI 变快"真正变成"组织级系统提速"的人智协同研发平台。
> 先建驾驭框架(Harness),再放 Agent 自主跑;先建安全网,再放大自主度。

### 核心论点(全文核心叙事,来自原料的思想内核)

> **个人提效已经发生,组织提效没有自然发生。**
> FarAI 研发流水线解决的,正是"个人变快之后,组织如何承接"。

### 产品四层架构(转写自 5+2 + Harness)

```
┌─────────────────────────────────────────────┐
│  ④ 治理与度量层                                │
│     风险分级 · Human-in-Loop · AI FinOps · 效能度量 │
├─────────────────────────────────────────────┤
│  ③ 人智协同平台(Delivery Workbench)            │
│     桌面智能体 · 云端智能体 · 任务/权限/审计 · Skill 治理 │
├─────────────────────────────────────────────┤
│  ② Harness 驾驭框架(工程底座,Agent 可控的前提)    │
│     CLI 化 · fullcheck · E2E · hooks · traceId · Agent OS │
├─────────────────────────────────────────────┤
│  ① 知识与本体底座                               │
│     本体网络 · 语义连接 · Agent 记忆 · 经验进化         │
└─────────────────────────────────────────────┘
```

### 四大场景(售前材料的场景展开轴,每个 2 页)

| 场景 | 解决的问题 | FarAI 能力 | 量化锚点(预估) |
|------|-----------|-----------|-----------------|
| **S1 智能需求闭环** | 需求不清、反复返工 | 编码 Agent 反读代码反向提问,需求进入开发前与真实系统碰撞 | 需求返工率 ↓40-50%(预估) |
| **S2 智能交付闭环** | AI 写了不敢合,质量靠人工把关 | Harness + fullcheck + 自动化测试,改完即可验证可发布 | 返工/缺陷率 ↓40-60%(预估) |
| **S3 智能知识底座** | Agent 找不到上下文,知识散落 | 本体网络语义连接,Agent 沿依赖找准确上下文 | 上下文获取 分钟级→秒级(预估) |
| **S4 智能治理与 FinOps** | AI 效能说不清、成本不可控 | 风险分级 + 效能度量 + Token ROI,先建安全网再放自主度 | AI 投入产出 可度量(预估) |

### 差异化(为什么是 FarAI)

1. **Harness 先行,不是卖工具** —— 别人卖 AI 编码工具,FarAI 卖"让 AI 在组织里可控跑起来"的驾驭框架。
2. **组织级系统提效,不止个人提效** —— 从个人效率升级到小队/产品线/组织级系统效率。
3. **四闭环 + 三层流动** —— 不只是 IDE 插件,是贯穿需求-交付-运营-进化的完整工艺。
4. **本体网络 + Agent 记忆** —— 让 Agent 越用越准,组织经验持续进化成能力资产。
