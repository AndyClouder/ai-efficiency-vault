# 知识分类

## 触发条件

- 用户说"整理一下""分类""帮我整理"
- 用户说"看看Inbox里有什么"
- 用户确认入库后说"帮我分类"
- 可设定每周/每日自动触发

## 工作流程

### 第一步：扫描 Inbox

列出 `0_Inbox/` 下所有 `status: inbox` 的笔记（**排除 `0_Inbox/raw/` 原文存证目录**），告知用户当前待处理数量。

### 第二步：逐篇分析

对每篇笔记，基于内容语义判断 PARA 归属：

- **P (1_Projects)**：有明确截止日期或阶段性目标的任务。特征：包含 deadline、交付物、里程碑等关键词
- **A (2_Areas)**：持续关注的职责领域，没有截止日期。特征：产品管理、团队管理、个人成长、技术积累等长期话题
- **R (3_Resources)**：按主题归档的参考资料。特征：行业报告、竞品信息、读书笔记、工具教程等"将来可能用到"的内容
- **A (4_Archives)**：已过时的、不再活跃的内容。特征：过期的项目文档、旧版方案、已废弃的流程

### 第三步：提出分类建议

对每篇笔记输出：

```
📄 笔记：xxx.md
📂 建议归属：2_Areas/产品管理/
📝 判断理由：（一句话解释为什么归到这里）
❓ 确认移动？（回复"可以"/"换到XX"/"跳过"）
```

### 第四步：执行移动

- 用户确认后执行文件移动
- 将 `status: inbox` 改为 `status: classified`
- 移动完毕后汇总报告："共处理N篇，移动N篇，跳过N篇"

### 第五步：更新索引与日志（铁律）

- 更新 `0_系统配置/INDEX.md`：将已分类笔记从「Inbox 待处理」移入对应 PARA 小节，修正链接路径
- 追加 `0_系统配置/LOG.md`：`## [YYYY-MM-DD] classify | 共N篇：移动N，跳过N`
- 收尾提示："要不要顺手把这批笔记编译进综合层？"（确认后触发「知识编译」）

## 分类决策规则

1. **有截止日** → 优先归 P（项目）
2. **纯参考资料、无行动意图** → 归 R（资源）
3. **关于个人提升、团队管理、产品方向** → 归 A（领域）
4. **超过6个月未更新且无引用** → 考虑归 Archives
5. **一张笔记可能同时属于多个分类** → 选最核心的一个，在笔记内添加交叉引用

## 注意事项

- 绝对不要自动移动，必须等人确认
- 判断理由必须具体，不能说"因为这是参考资料"（太模糊）
- 不确定时标注"不确定，建议归类为R"
- 用户可以说"全确认"批量确认所有建议
