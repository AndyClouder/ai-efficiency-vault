# 类型：component(组件图 / 模块依赖)

> 模块卡片 + 依赖连线(可交叉)。用于模块依赖关系、组件调用图。与 architecture 的区别：component 允许**任意方向连线**(包括交叉、回流)，不强制分层；与 flowchart 的区别：component 是**静态依赖关系**，不强调先后顺序。

## 1. 构图骨架

```
       [Auth] ─────→ [User DB]
         │
         ↓
       [Gateway] ←─── [Config]
         │   ╲
         ↓    ╲
      [Service A]   [Service B]
         │              │
         └────→ [Cache] ←┘
```

- **节点**：组件卡片(矩形，带标题 + 类型/技术栈)
- **连线**：带箭头的依赖线(A → B 表示 A 依赖 B)
- **布局**：按依赖方向尽量从上到下/从左到右，但允许必要的交叉

## 2. 节点规则

| 字段 | 内容 |
|---|---|
| 组件名 | AuthService / PaymentGateway 等，≤6 字 |
| 类型/技术 | 副标题(Java / gRPC / REST) |

节点画法同 architecture 的卡片，但**不强制同层等宽**——每个组件按内容定尺寸。

## 3. 连线规则

- **依赖箭头**：A → B(A 依赖 B)，实线 + 箭头
- **接口/契约**：可用空心箭头或棒棒糖符号(圆+线)
- **标签**：可选，标明依赖类型("uses" / "implements" / "API")
- **减少交叉**：布局时尽量让依赖方向一致(都向下或都向右)；实在交叉就用正交折线 `<path>` 走清晰路径

## 4. 子系统框

把强相关的几个组件圈进一个虚线框，标注子系统名：

```
┌─ 认证子系统 ─────────────┐
│  [Auth] → [Token Service] │
└───────────────────────────┘
        │
        ↓
   [Business Logic]
```

## 5. 默认画布

1280×720(16:9)。组件 5-8 个最舒适；超过 10 个考虑拆图或用 hierarchy。

## 6. 参考模板

`templates/charts/module_composition.svg` —— 多模块 + 连线关系。

## 7. 红线

- ❌ 不画无方向的依赖(必须明确谁依赖谁)
- ❌ 连线交叉太多导致看不清(优先重排布局减少交叉)
- ❌ 节点拥挤(留足间距让连线可读)
- ✅ 依赖方向整体一致(主向下/向右)
