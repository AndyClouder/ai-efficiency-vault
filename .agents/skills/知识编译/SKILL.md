# 知识编译

> 本知识库的核心引擎。让知识从"被归档的笔记"升级为"持续复利的综合层"。
> 一篇新来源进来，不只是存好，而是让全库已有的结论变得更强——或者被推翻。
> 借鉴 Karpathy《LLM Wiki》模式：wiki 是 compounding artifact（复利型资产），编译一次，持续保鲜。

---

## 触发条件

- 「知识入库」或「网络调研」完成并经用户确认后，自动触发一次编译
- 用户说："编译一下""更新综合页""把这篇编译进去"
- 用户说："这篇和哪些相关""找关联""帮我连接"（原「知识关联」触发词，由本 skill 承接）
- 用户请求全库编译："全库编译""重建综合层"
- 用户手动 `/编译`

## 综合层结构（5_Wiki/）

| 子目录 | 页面类型 | 示例 |
|--------|----------|------|
| `5_Wiki/实体页/` | 公司、人物、产品、工具 | 《埃森哲》《Claude Code》 |
| `5_Wiki/概念页/` | 方法论、概念、框架 | 《FDE模式》《PARA方法》 |
| `5_Wiki/论点页/` | 有争议的、正在演化的论点 | 《AI对IT服务外包的冲击》 |
| `5_Wiki/问答页/` | 由「知识问答」回灌的有价值问答 | 《为什么FDE比传统外包毛利高》 |

综合页与普通笔记的本质区别：**普通笔记记录单一来源说了什么；综合页记录多个来源加起来意味着什么。**

### 综合页标准格式

```markdown
---
type: entity | concept | thesis | qa
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: N
tags: [xxx, yyy]
---

# 页面标题

## 当前综合结论
（3-8 句，代表截至最近一次编译的最新理解）

## 关键事实与观点
- 事实/观点 A（来源：[[某笔记]]，YYYY-MM-DD）
- 事实/观点 B（来源：[[某笔记]]，YYYY-MM-DD）

## ⚔️ 矛盾与张力
- [[来源A]] 认为 X，但 [[来源B]]（更新）认为非X —— 状态：未解决 / 已由新证据解决
（无矛盾时保留小节，写"暂无"）

## 演化日志
- YYYY-MM-DD：因 [[新来源]] 加入，修订了关于XX的结论
```

## 工作流程

### 第一步：确定编译范围

- 默认：刚入库/刚调研完成的笔记
- 用户指定：某篇笔记、某个目录、或"全库编译"
- 全库编译前先告知预估工作量，等用户确认

### 第二步：识别触及的综合页

通读新笔记，回答三个问题：

1. **它提到了哪些已有综合页？**（读 `0_系统配置/INDEX.md` 的 5_Wiki 部分定位）
2. **它是否推翻、削弱或强化了某个综合页的现有结论？**
3. **它是否值得新建综合页？**（判断标准：该实体/概念/论点已被 ≥ 2 个来源触及，或用户明确关注）

一篇有信息量的来源，通常会触及 3-10 个综合页。

### 第三步：执行编译

对每个触及的综合页：

- **强化**：新证据支持现有结论 → 在「关键事实与观点」追加条目，注明来源和日期
- **矛盾**：新证据与现有结论冲突 → **绝不静默覆盖**。在「⚔️ 矛盾与张力」显式记录双方及出处，等积累更多证据或用户裁决后才改写「当前综合结论」
- **修订**：证据足以改变结论 → 改写「当前综合结论」，并在「演化日志」记一笔为什么改
- **新建**：需要新页 → 按标准格式创建，向用户提议一句

同时铺设双向链接（原「知识关联」职责）：

- 综合页 ↔ 来源笔记：编译时天然形成
- 来源笔记 ↔ 来源笔记：发现语义相关的普通笔记，在双方末尾「相关笔记」小节追加 Wiki Link，关联原因用 HTML 注释标注
- 已存在的关联不重复添加；单篇笔记关联数 ≤ 5 对；置信度低时标注 `<!-- 关联原因：待确认 -->`

### 第四步：更新索引与日志（铁律）

- 更新 `0_系统配置/INDEX.md`：新建的综合页登记一行（链接 + 一句话摘要 + 来源数）；被修订的综合页更新摘要
- 追加 `0_系统配置/LOG.md`：`## [YYYY-MM-DD] compile | 来源标题 → 触及 N 页（新建 X，修订 Y，矛盾 Z）`

### 第五步：输出编译报告

```
🔨 编译报告 — 《来源标题》

触及综合页：N 个
| 综合页 | 动作 | 说明 |
|--------|------|------|
| [[埃森哲]] | 修订 | 组织架构调整信息更新了"当前综合结论" |
| [[FDE模式]] | 强化 | 新增 1 条支持性证据 |
| [[AI对外包的冲击]] | ⚔️ 矛盾 | 新来源与 6 月综述结论冲突，已标注待裁决 |

新建综合页：《XXX》（已征求意见）
新增笔记间关联：N 对
INDEX.md / LOG.md 已更新 ✓
```

## 注意事项

- 综合页由 AI 全权维护，用户只读不写；来源笔记的**正文绝不修改**，只追加「相关笔记」小节
- 矛盾处理是本 skill 的灵魂：**记录矛盾比消除矛盾更有价值**，静默覆盖旧结论是最严重的违规
- 每条结论必须可溯源（Wiki Link 到来源笔记），无出处的结论不写入综合页
- 新建综合页宁缺毋滥：单一来源提到的边缘实体不建页，等第二个来源出现
- 全库编译可能耗时较长，先告知用户"正在编译..."
