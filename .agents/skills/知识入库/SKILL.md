# 知识入库

## 触发条件

- 用户说"记一下""存一条""入库""保存这个"
- 用户直接粘贴长文本（>200字）或 URL
- 用户说"把这个网页存下来""记录一下这个"

## 工作流程

### 第一步：接收输入

识别用户提供的知识来源类型：
- **URL**：网页链接，用 Web Fetch 获取内容
- **粘贴文本**：用户直接粘贴的纯文本或 Markdown
- **文件路径**：本地文件路径，读取文件内容

### 第二步：原文保全（新增铁律）

**先存原文，再做摘要。** 将获取到的原始内容全文写入 `0_Inbox/raw/YYYY-MM-DD_标题关键词_raw.md`（含来源 URL 和抓取时间），此文件**永不修改、永不删除**（归档除外）。

原因：结构化摘要是有损压缩。半年后若发现摘要理解有误、或「知识编译」需要重新审视原始证据，原文是唯一可信底座。raw 文件不参与分类和关联，只作为结构化笔记 frontmatter 中 `raw:` 字段指向的存证。

### 第三步：提取核心信息

从原始内容中提取：
- **标题**：自动生成一个简洁准确的中文标题（10-20字）
- **来源**：URL 或文件名
- **日期**：当前日期
- **核心内容**：保留原文关键信息，去除广告、导航、页脚等噪音
- **关键标签**：提取 3-5 个核心关键词作为标签

### 第四步：生成结构化笔记

按照以下模板写入 `0_Inbox/`：

```
---
date: YYYY-MM-DD
source: 原始来源URL或文件名
raw: 0_Inbox/raw/YYYY-MM-DD_标题关键词_raw.md
tags: [标签1, 标签2, 标签3]
status: inbox
---

# 标题

## 核心要点

- 要点1
- 要点2
- 要点3

## 原文摘要

（保留原文关键信息的结构化摘要）

## 来源

- 原文链接/文件路径
- 保存日期：YYYY-MM-DD
```

### 第五步：更新索引与日志（铁律）

- 更新 `0_系统配置/INDEX.md`：在「Inbox 待处理」小节登记一行（链接 + 一句话摘要）
- 追加 `0_系统配置/LOG.md`：`## [YYYY-MM-DD] ingest | 笔记标题`

### 第六步：告知用户

入库完成后告知用户：
- 文件已保存到 `0_Inbox/文件名.md`（原文存证于 `0_Inbox/raw/`）
- 提示："需要分类到 PARA 目录、并编译进综合层吗？"（确认后依次触发「知识分类」→「知识编译」）

## 注意事项

- 不要对内容做价值判断，什么都存
- 标题要能让人一周后看到还能想起这是什么
- 标签用中文，3-5个，不要太泛（如"AI"太泛，用"AI效能"更好）
- 如果用户连续粘贴多条内容，每条单独存一个文件
