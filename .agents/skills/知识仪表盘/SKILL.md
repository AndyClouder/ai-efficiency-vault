# 知识仪表盘

## 触发条件

- 用户说"看下状态""仪表盘""统计""知识库怎么样"
- 用户说"本周总结""这周新增了多少"
- 每周日自动触发（用户可在系统配置中设定频率）

## 工作流程

### 第一步：全量扫描统计

遍历知识库全部 Markdown 文件，统计：

**基础指标：**
- 总笔记数、各 PARA 目录的笔记数量
- Inbox 待处理数量
- 本周新增笔记数（基于 frontmatter `date` 字段）
- 本周修改笔记数

**质量指标：**
- 孤立笔记数（无任何 Wiki Link 的笔记）
- 死链接数
- 低质量笔记数（<200字 或 无 frontmatter）
- 无标签笔记数

**活跃度指标：**
- 本周活跃的笔记（被修改或新增）
- 最常被引用的笔记 Top 5（被 Wiki Link 引用次数最多的笔记）
- 最大的知识领域（2_Areas 中笔记数最多的子目录）

### 第二步：更新 DASHBOARD.md

更新 `0_系统配置/DASHBOARD.md` 中的「基础指标」和「质量指标」表格。

在「趋势记录」表格末尾追加一行：

```
| YYYY-MM-DD | 总笔记数 | 本周新增 | Inbox待处理 | 孤立数 | 死链数 | 备注 |
```

### 第三步：输出摘要

```
📊 知识库仪表盘 — 2026年W25

📈 基础数据
- 总笔记：N 篇（本周 +X）
- Inbox 待处理：N 篇
- 分布：P项目 N 篇 / A领域 N 篇 / R资源 N 篇 / A归档 N 篇

🔍 质量健康度
- 孤立笔记：N 篇
- 死链接：N 个
- 低质量笔记：N 篇
- 关注：XXX（如果有异常数字，给出提醒）

💡 建议
- （基于数据给出 1-2 条操作建议）
```

## 注意事项

- DASHBOARD.md 的「趋势记录」表格只追加不覆盖
- 如果用户一周内多次触发，只更新指标表格，趋势记录只在周日追加
- 当发现异常（如死链突然增多、Inbox 积压超过20篇），主动提醒用户
- 扫描全库可能较慢，先告知用户"正在扫描..."
