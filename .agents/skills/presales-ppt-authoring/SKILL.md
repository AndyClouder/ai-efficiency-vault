# 售前 PPT 编写

> 售前 PPT 的端到端方法论:理解客户 → 规划章节 → 编写内容 → 套品牌 → 生成 PPTX → 归档。本 skill 是总指挥,风格套用调 farai-style-conversion,PPT 物理生成调 ppt-master。

---

## 触发条件

- 用户说:"做售前 PPT" "写售前材料" "客户汇报 PPT" "售前方案 PPT" "投标演示稿"
- 用户说:"给 X 客户做个 PPT" "帮我把这份需求做成 PPT" "汇报材料"
- 用户提供客户需求/背景材料,要求制作汇报 PPT
- 用户键入:`/售前PPT` `/汇报材料`

**与其他 skill 的边界**:
- 本 skill **主导**售前 PPT 全流程(从需求理解到 PPTX 交付)
- 需要套 FarAI 品牌风格时 → 调 **farai-style-conversion** 产 spec_lock
- PPT 物理生成(SVG→PPTX) → 调 **ppt-master** 执行
- 客户需求原文存档 → 用 **知识入库** 的原文保全逻辑(存到 `1_Projects/<客户>/`)
- 用户只要"画个流程图/架构图"不要做完整 PPT → 走 **图绘大师**,不是本 skill

## 工作流程(7 步,端到端)

### 第一步:需求澄清(必做,不可跳过)

用 3 个问题对齐方向,避免做出来不对路:

1. **客户行业定位**:客户是什么行业/什么类型企业?(决定话术基调、案例引用、痛点侧重)
2. **交付范围**:全套场景展开 vs 总体概览?(决定页数:全套 23-30 页 vs 概览 12-15 页)
3. **目标受众**:客户决策层 vs 业务+IT 部门 vs 内部售前用?(决定价值/技术细节比重)

用 AskUserQuestion 一次性问出(三个问题并列,带推荐选项)。用户答完才进入下一步。

> **若用户已提供客户需求材料**:先读完材料,再带着理解问这 3 问(选项可更精准)。

### 第二步:需求原文存档(原文保全铁律)

把客户提供的原始需求**全文**存到 `1_Projects/<客户名>AI智能化需求/客户需求原文.md`:

- frontmatter:`date / source: 客户提供 / tags: [原始材料, 客户需求, <客户名>]`
- 正文:客户原话,**一字不改**(结构化整合另建主档)
- 同步建项目主档 `<客户名>AI智能化需求.md`:项目目标、客户背景、痛点、需求方向、关键交付物、时间线

> 原因:半年后若要复盘或改稿,客户需求原文是唯一可信底座。结构化摘要是有损压缩,原文不可丢。

更新 `0_系统配置/INDEX.md`(1_Projects 区)+ `LOG.md`(`ingest` 条目)。

### 第三步:客户理解(决策层视角)

从需求提炼三层认知,写入项目主档:

1. **客户定位**:一句话说清客户是谁、做什么、行业地位(如"全球商业地产五大行之一")
2. **业务特点**:3-5 个影响方案设计的业务特征(如"管理项目多、信息分散、决策链复杂")
3. **痛点清单**:每个痛点必须能关联到一个 AI 切入点(痛点 → 我们能解决)

**关键判断**:痛点不是罗列客户抱怨,而是找出"AI 能切入的高价值环节"。若某个痛点 AI 解决不了,就不放进售前材料(避免开空头支票)。

### 第四步:章节规划

读取 `references/chapter-structure.md`,按客户特点和受众选范式:

| 范式 | 适用 | 页数 |
|------|------|------|
| **标准售前** | 4-6 场景的中大型方案(最常用) | 23-30 |
| **痛点驱动** | 竞标/强竞争场景 | 20-25 |
| **产品演示** | 产品推介 | 18-22 |
| **高管简报** | 30 分钟内高管汇报 | 10-15 |

产出大纲(Markdown),每页含:
- **页码 + 页名**
- **layout**(布局:卡片网格/流程横排/2×2矩阵/中心辐射/单列居中)
- **title**(页面标题,要是结论而非标签——pyramid 原则)
- **core message**(这页存在的唯一理由,一句话)
- **content blocks**(内容块,标注呈现形式:prose/bullet/keyword)

大纲先给用户确认,再进入内容编写。

### 第五步:内容编写

按大纲逐页填内容。三条铁律:

**铁律 1:每页一个 core message**
每页只讲一件事。core message 写不出 → 这页该砍或合并。pyramid 模式下,页面标题本身就是结论(如"四大场景串联成完整业务闭环"),不是标签(如"业务闭环")。

**铁律 2:痛点 → 方案 → 价值 三段式**
每个场景至少 2 页:① 痛点 + 流程 ② 能力 + 价值。价值要量化(查 `references/value-estimation.md`)。

**铁律 3:量化指标必标"预估"**
所有未经验证的数字必须标注"(预估)"。优先区间值("↑50%+")而非精确数字。用户提供真实数据则用真实,但仍建议保留预估作为对照。

读取 `references/audience-playbook.md` 按受众调整话术比重:
- **决策层**:重价值/ROI/闭环,技术架构只 1 页概览,量化指标放显眼位置
- **业务+IT**:重方案落地、系统集成、实施路径、数据安全
- **内部售前**:重能力清单、差异化优势、报价框架

### 第六步:风格套用 + PPT 生成

询问用户:"是否套用法本 FarAI 品牌风格?"(默认是,因为 FarAI 是公司法本的主品牌)

- **套 FarAI(默认)**:调用 **farai-style-conversion** skill → 它读 FarAI 品牌规范 → 产出 spec_lock.md(预填品牌色/字号/版式)→ 保存到 ppt-master 项目目录
- **不套(自定义)**:直接进入 ppt-master,在 Step 4 八项确认时由用户定风格

调用 **ppt-master** skill,把本 skill 产出的内容大纲 + spec_lock 交给它:
- ppt-master 会走完 Strategist(design_spec.md)→ Executor(逐页 SVG)→ 质检 → 后处理 → 导出 PPTX
- 本 skill 在 ppt-master Step 4 八项确认前完成内容规划,在 Step 6 前完成风格锁定

**协作契约**:本 skill 产出三样东西给 ppt-master:
1. `design_spec.md` 的 §IX 内容大纲(每页 layout/title/core message/content)
2. `spec_lock.md`(由 farai-style-conversion 产出,FarAI 风格下所有数值预填)
3. 项目目录路径(`projects/<客户名>售前方案_ppt169_<date>/`)

### 第七步:归档(双铁律)

PPT 生成完成后:

1. **PPT 路径回写项目主档**:在 `1_Projects/<客户名>AI智能化需求.md` 的"关键交付物"登记 PPT 文件路径、规格、结构
2. **更新时间线**:主档的里程碑表标记"PPT v1.0 已生成"
3. **更新 INDEX/LOG**:INDEX 摘要更新(标注 PPT 已生成);LOG 追加 `## [date] compile | <客户名>售前 PPT 生成(ppt-master,N 页,FarAI 风格)`

告知用户:文件位置、规格、结构概览、下一步建议(如"打开 PPT 检查,如需局部调整告诉我页码")。

## 受众适配速查

读取 `references/audience-playbook.md` 获取完整对照表。速查:

| 受众 | 话术比重 | 技术架构 | 量化指标 | 页数 |
|------|---------|---------|---------|------|
| **决策层** | 价值 70% / 技术 30% | 1 页概览即可 | 放显眼位置,大字号 | 15-25 |
| **业务+IT** | 价值 40% / 技术 60% | 详细(架构+集成+实施) | 作为支撑证据 | 23-30 |
| **内部售前** | 能力 50% / 价值 30% / 差异化 20% | 中等 | 用于说服客户 | 20-25 |

## 与 ppt-master 的协作契约

本 skill 与 ppt-master 的分工:

| 阶段 | 本 skill 负责 | ppt-master 负责 |
|------|--------------|----------------|
| 内容规划 | ✅ 章节大纲 + 每页 core message + content | — |
| 风格锁定 | ✅ 调 farai-style-conversion 产 spec_lock | — |
| design_spec.md | ✅ 提供 §IX 内容大纲 | 整合为完整 design_spec |
| Strategist 八项确认 | ✅ 预填推荐值(基于受众和风格) | 呈现给用户确认 |
| SVG 生成 | — | ✅ 逐页生成 |
| 质检 + 后处理 + 导出 | — | ✅ 产出 PPTX |
| 归档 | ✅ PPT 路径回写 + INDEX/LOG | — |

**关键**:本 skill 不生成 SVG,不直接操作 python-pptx。所有 PPT 物理生成交给 ppt-master,避免职责重叠。

## 注意事项

1. **原文保全铁律**——客户需求原文一字不改地存档,结构化整合另建主档。半年后改稿的底座。
2. **量化必标"预估"**——所有未经验证的数字标"(预估)",优先区间值。售前阶段给精确数字是给自己挖坑。
3. **决策层不堆技术细节**——决策层方案的技术架构最多 1 页概览,重点在价值和闭环。技术细节多了高管看不下去。
4. **每页一个 core message**——讲不出这页存在的唯一理由,就砍掉或合并。宁可页少而精,不要页多而散。
5. **价值闭环必有**——售前 PPT 必须有一个"完整业务闭环"页(如"信息发现→...→结果复盘"),这是决策层最爱的叙事。客户自己提的闭环原话要放重头。
6. **四镜像同步**——本 skill 修改后,四个目录的 SKILL.md + references 必须一致(改源 → cp 到四个运行时副本)。
7. **INDEX/LOG 双铁律**——每个 skill 执行完毕必须更新 INDEX.md 并追加 LOG.md,无一例外。
8. **风格默认 FarAI**——法本信息出品默认套 FarAI 品牌,除非用户明确要其他风格。FarAI 是公司主品牌,一致性是专业感的来源。
