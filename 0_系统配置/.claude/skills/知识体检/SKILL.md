# 知识体检

> 知识库的 lint。原「知识仪表盘」（看状态）与「知识清理」（找问题）做的是同一次全库扫描，故合并为一：**扫描一次，先报告健康度，再给分级修复建议**。
> 新增两项只有综合层存在后才可能的检查：页面间观点矛盾、被新来源推翻的陈旧结论。

---

## 触发条件

- 用户说："看下状态""体检""仪表盘""统计""知识库怎么样""本周总结"
- 用户说："清理一下""去重""知识库瘦身""检查死链"
- 每周日自动触发（用户可在系统配置中设定频率）
- 用户手动 `/体检`

---

## 工作流程

### 第一步：全量扫描（只扫一遍）

遍历全库 Markdown 文件，一次性采集两类数据：

**A. 健康指标（原仪表盘职责）**

- 基础：总笔记数、各 PARA 目录分布、`5_Wiki/` 综合页数、Inbox 待处理数、本周新增/修改数
- 质量：孤立笔记数（无任何 Wiki Link）、死链数、低质量笔记数（<200字 或 无 frontmatter）、无标签笔记数
- 活跃度：本周活跃笔记、被引用 Top 5、最大知识领域
- **复利指标（新增）**：综合页总数、平均每页来源数、本周被修订的综合页数、未解决矛盾数——这组数字衡量知识库是在"堆积"还是在"复利"

**B. 问题清单（原清理职责）**

- 🔴 死链接：`[[Wiki Link]]` 目标不存在
- 🟡 过期内容：`status: archived` / `expired: true` / 超 12 个月未动的时间敏感内容
- 🟡 疑似重复：标题与正文语义相似度 > 80%
- 🟡 **观点矛盾（新增）**：综合页「⚔️ 矛盾与张力」中状态为"未解决"且超过 30 天的条目
- 🟡 **陈旧结论（新增）**：综合页的「当前综合结论」更新日期早于其最新来源笔记的日期（说明有来源入库后没编译）
- 🟢 低质量笔记：<200 字、无 frontmatter、孤立、无标签
- 🟢 **知识缺口（新增）**：LOG.md 中多次出现但库内证据薄弱的主题 → 建议发起「网络调研」

### 第二步：更新 DASHBOARD.md

- 更新「基础指标」「质量指标」表格，新增「复利指标」表格
- 「趋势记录」表格末尾追加一行（只追加不覆盖；一周内多次触发只更新指标，趋势记录仅周日追加）

### 第三步：输出体检报告

```
🩺 知识库体检 — 2026年W27

📈 基础数据
- 总笔记：N 篇（本周 +X）｜综合页：N 个｜Inbox 待处理：N 篇
- 分布：P N / A N / R N / A N / Wiki N

♻️ 复利健康度
- 综合页平均来源数：N ｜ 本周被修订综合页：N
- 未解决矛盾：N 条 ｜ 待编译来源：N 篇

🚦 问题清单
🔴 死链 N 个 ｜ 🟡 过期 N 篇、疑似重复 N 对、矛盾积压 N 条、陈旧结论 N 页 ｜ 🟢 低质量 N 篇、知识缺口 N 个

（各类问题的明细表，按 🔴🟡🟢 分级列出，含建议操作）

💡 建议
- （基于数据给出 1-3 条，如"3 篇来源入库后未编译，建议先跑 /编译"）
```

### 第四步：等待用户指令

报告生成后不执行任何修复，等待明确指令：

- "归档全部过期内容" / "清理死链" / "先处理🔴" → 执行对应类别
- "矛盾第 2 条按新来源裁决" → 转交「知识编译」修订综合页
- "补 X 的资料" → 转交「网络调研」
- "跳过" → 不做操作

### 第五步：更新日志（铁律）

追加 `0_系统配置/LOG.md`：`## [YYYY-MM-DD] lint | 全库体检：N 篇 / 问题 🔴X 🟡Y 🟢Z / 已修复：…`

---

## 注意事项

- 绝对不自动删除任何文件，始终等人确认；删除移入回收站，不永久删除（如可能）
- 重复判断仅作"疑似"标注，不是精确科学
- 扫描全库可能较慢，先告知"正在扫描..."
- 发现异常（死链激增、Inbox 积压 > 20、矛盾积压 > 5）主动提醒
- 体检报告归档一份到 `0_系统配置/体检报告/YYYY-MM-DD.md` 留痕
