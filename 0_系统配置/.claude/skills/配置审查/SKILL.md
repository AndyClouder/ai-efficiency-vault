# 配置审查

> 知识库的"体检医生"。三方对账：注册表写了什么、配置说明写了什么、磁盘实际有什么，逐条核对，发现偏差只报告不擅自修改，等用户指令。
> 目的：防止"注册表说路径在 A，实际文件在 B"这类隐性漂移，保证系统长期可运转。

---

## 触发条件

- 用户说："检查同步""审查配置""对齐注册表""配置审查""一致性检查"
- 用户说："配置对不对""路径还对吗""skill 同步了吗"
- 定期维护时手动触发（建议每月一次，或增删 skill 后必跑一次）
- 用户手动 `/配置审查`

---

## 核心原则

1. **只读审查，不擅自修改** —— 发现偏差只报告，所有修复动作必须等用户明确指令
2. **三方对账** —— 不只看"文件存不存在"，而是三方信息源交叉验证
3. **分级报告** —— 偏差按严重程度分级，让用户能快速判断优先级
4. **落盘留痕** —— 报告写入文件，可追溯历史

---

## 三方数据源

| 数据源 | 路径 | 内容 |
|--------|------|------|
| **① 路径注册表** | `0_系统配置/知识库路径注册表.md` | 系统登记的所有核心路径（PARA 目录、身份文件、系统配置、Skills 镜像路径） |
| **② 系统配置说明** | `0_系统配置/系统配置说明.md` | 对外说明文档（含 skill 清单、文件结构、记忆系统说明） |
| **③ 实际磁盘** | vault 根目录扫描 | 真实存在的文件和目录 |

---

## 工作流程

### 第 1 步：加载三方数据

读取并解析：

1. **路径注册表** `0_系统配置/知识库路径注册表.md`
   - 提取所有表格中「当前路径」列的值
   - 分类：PARA 目录（5 条）、核心身份文件（5 条）、系统配置（3 条）、Skills 镜像路径（4 条）

2. **系统配置说明** `0_系统配置/系统配置说明.md`
   - 提取 skill 清单（数量 + 名称）
   - 提取文件结构说明
   - 提取记忆系统文件清单

3. **实际磁盘**：用 Glob 扫描
   - 5 个 PARA 目录是否存在、是否非空
   - 注册表登记的所有 .md 文件路径是否存在
   - 4 个 Skills 镜像目录各自的文件清单

### 第 2 步：执行 4 项检查

---

#### 检查 ①：注册表路径 vs 实际磁盘

逐一验证注册表登记的**每一条路径**是否在磁盘真实存在：

**对 PARA 目录**（5 条）：验证目录存在 + 至少含 `.gitkeep` 或内容
**对核心 .md 文件**（SOUL/USER/MEMORY/PREFERENCE/INVENTORY）：验证文件存在 + 非空 + frontmatter 可解析
**对系统配置文件**（DASHBOARD/CLAUDE/AGENTS）：同上
**对 Skills 镜像路径**（4 条）：验证目录存在 + 非空

**偏差判定：**
- 🔴 路径不存在（目录/文件丢失）
- 🟡 文件存在但为空，或 frontmatter 损坏无法解析
- 🟢 无偏差

输出格式：
```
### ① 注册表路径 vs 实际磁盘
| 注册路径 | 类型 | 状态 | 说明 |
|----------|------|------|------|
| 0_Inbox/ | PARA目录 | ✅ | 含 .gitkeep |
| 0_系统配置/SOUL.md | 核心文件 | ✅ | 41 行 |
| ... | ... | ... | ... |
```

---

#### 检查 ②：Skills 四镜像一致性

对比 4 个 Skills 目录的文件清单和内容：

| 镜像 | 路径 | 角色 |
|------|------|------|
| 源1 | `0_系统配置/.agents/skills/` | Codex 配置源 |
| 源2 | `0_系统配置/.claude/skills/` | Claude 配置源 |
| 运行时1 | `.agents/skills/` | Codex 运行时 |
| 运行时2 | `.claude/skills/` | Claude 运行时 |

**比对两层：**

**层 A — 文件清单比对**：
- 用 Glob `**/*.md` 扫描 4 个目录，得到各自的相对路径列表（相对各自 skills/ 根）
- 比对 4 个清单是否完全一致（集合差异）

**层 B — 内容 MD5 比对**：
- 对 4 个清单中都存在的文件，逐一读取内容计算哈希（用 Bash `certutil -hashfile` 或读取后比较）
- 比对同名文件在 4 处的内容是否一致

**偏差判定：**
- 🔴 某镜像 skill 数量不一致（如源1有 9 个 skill，运行时1只有 8 个）
- 🔴 同名 skill 在不同镜像内容不同（内容漂移）
- 🟡 文件清单一致但个别文件 MD5 不同（内容微调未同步）
- 🟢 4 处完全一致

输出格式：
```
### ② Skills 四镜像一致性
| 镜像目录 | skill 数 | .md 文件数 |
|----------|---------|-----------|
| 0_系统配置/.agents/skills/ | 9 | 29 |
| 0_系统配置/.claude/skills/ | 9 | 29 |
| .agents/skills/ | 9 | 29 |
| .claude/skills/ | 9 | 29 |

清单差异：无
内容差异：无 / [列出 MD5 不一致的文件]
```

> 💡 MD5 比对较慢（约 100+ 文件）。比对前先比文件清单，清单一致再比内容；清单就不一致时直接报告，跳过 MD5。

---

#### 检查 ③：配置说明 vs 实际 skill 清单

对比「系统配置说明.md 写的 skill 清单」与「磁盘实际 skill 目录」：

**从配置说明提取：**
- skill 总数（如"10 个"）
- skill 名称列表（从编号列表提取）

**从磁盘提取：**
- 4 个镜像目录任取一个，列出 skills/ 下的子目录名

**偏差判定：**
- 🔴 数量不符（如说明写 10，实际 9）
- 🔴 名称不符（说明里有 autoresearch，磁盘没有）
- 🟢 数量和名称完全一致

输出格式：
```
### ③ 配置说明 vs 实际 skill 清单
- 配置说明登记：10 个（autoresearch、图绘大师、新手引导、...）
- 磁盘实际：9 个（图绘大师、新手引导、...）
- 🔴 数量不符：说明比实际多 1 个
- 🔴 幽灵 skill：autoresearch（说明里有，磁盘没有）
```

---

#### 检查 ④：核心 .md 文件完整性

验证注册表登记的核心身份/配置文件是否健康：

**对每个文件检查：**
1. 存在性（Glob 能找到）
2. 非空（行数 > 0）
3. frontmatter 可解析（开头是 `---`，含 `description` 字段）
4. 关键字段非占位符（USER.md 的"名字"不是"待补充"算提示级，不算错误）

**偏差判定：**
- 🔴 文件丢失
- 🟡 文件为空 / frontmatter 损坏
- 🟢 文件健康

输出格式：
```
### ④ 核心 .md 文件完整性
| 文件 | 存在 | 行数 | frontmatter | 状态 |
|------|------|------|-------------|------|
| SOUL.md | ✅ | 41 | ✅ | 🟢 |
| USER.md | ✅ | 34 | ✅ | 🟢（名字待补充） |
| MEMORY.md | ✅ | N | ✅ | 🟢 |
| ... | ... | ... | ... | ... |
```

---

### 第 3 步：生成分级报告

汇总 4 项检查，输出总览 + 分级偏差清单：

```
## 🔍 配置审查报告 · {YYYY-MM-DD HH:MM}

### 总览
- 检查项：4 项
- 通过：x 项
- 发现偏差：y 处
  - 🔴 严重：a 处
  - 🟡 警告：b 处
  - 🟢 提示：c 处

### 详细结果
[依次粘贴上述 4 个检查小节的输出]

### 🔧 建议的修复动作（等你指令）

#### 🔴 严重（影响系统运转，建议优先处理）
1. **[偏差描述]**
   - 可选修复：
     - A) [动作1] 
     - B) [动作2]
   - 建议：[推荐哪个及原因]

#### 🟡 警告（影响一致性）
2. **[偏差描述]**
   - 修复动作：[...]

#### 🟢 提示（信息性）
3. **[偏差描述]**
   - 修复动作：[...]

---
⏸️ 我没有做任何修改。说"修"或指定具体动作（如"修第1项，选A"），我再动手。
```

### 第 4 步：落盘报告

将上述报告写入：
`0_系统配置/配置审查报告/{YYYY-MM-DD}.md`

> 报告统一存放在 `0_系统配置/配置审查报告/` 子目录下，文件名只取日期（如 `2026-06-24.md`），不重复前缀——目录名已表明用途。避免污染 `0_系统配置/` 根目录。

frontmatter 格式：
```yaml
---
description: 配置审查报告，记录本次三方对账结果
date: {YYYY-MM-DD}
checks: 4
deviations: {总偏差数}
critical: {严重数}
warning: {警告数}
info: {提示数}
---

# 配置审查报告 · {YYYY-MM-DD HH:MM}

[报告正文]
```

> 多次审查时每次生成新文件（按日期），不覆盖历史报告，便于追溯。

### 第 5 步：等待用户指令

报告输出后**停止**，把控制权交还用户。

**用户可能的后续指令：**
- "修第 N 项" / "修所有严重的" → 执行对应修复
- "修第 1 项，选 A" → 执行用户指定的方案
- "先不修" / "知道了" → 结束，不做任何修改
- 用户指定具体修复逻辑 → 按用户说的做

**修复完成后**：重新跑一遍审查，确认偏差已消除，输出修复后对比。

---

## 严重程度分级标准

| 级别 | 含义 | 典型场景 | 处理建议 |
|------|------|----------|----------|
| 🔴 严重 | 影响系统运转 | 注册表核心路径丢失、skill 镜像数量不一致、配置说明与实际 skill 不符 | 优先处理 |
| 🟡 警告 | 影响一致性 | 核心 .md 文件空/损坏、镜像内容 MD5 不一致 | 尽快处理 |
| 🟢 提示 | 信息性 | USER.md 字段仍为"待补充"、注册表未登记新文件 | 知晓即可 |

---

## 注意事项

1. **绝不擅自修改** —— 这是本 skill 的核心原则。发现偏差只报告，所有修复必须等用户明确指令
2. **三方交叉验证** —— 不要只信一方。注册表、配置说明、磁盘三方都要看，偏差往往是某一方没跟上
3. **MD5 比对优化** —— 先比文件清单（快），清单一致再比内容；清单不一致时直接报告清单差异，跳过 MD5
4. **报告要可追溯** —— 每次审查落盘到独立文件（按日期命名），历史报告不覆盖
5. **修复后要复检** —— 用户指令修复后，重新跑一遍审查确认偏差消除
6. **扫描前告知用户** —— "正在扫描三方数据，约需 N 秒..."，避免用户以为卡住
7. **现有偏差不是 bug** —— 本 skill 发现的偏差（如当前 autoresearch 在说明里但磁盘没有）是历史遗留，客观报告即可，不要替用户判断该不该删
