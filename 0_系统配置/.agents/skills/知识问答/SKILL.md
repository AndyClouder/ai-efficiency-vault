# 知识问答

> 知识库的消费端。建库不是目的，用库才是。
> 关键机制：**好答案不该消失在聊天记录里**——有价值的问答回灌进 5_Wiki/，让"提问"和"投喂"一样参与复利。

---

## 触发条件

- 用户说："根据知识库…""库里怎么说""我们之前存过什么关于 X 的"
- 用户提出需要跨笔记综合的问题："帮我对比 A 和 B""总结一下 X 的演变""分析 Y 的趋势"
- 用户手动 `/问答 [问题]`

**与其他 skill 的边界**：
- 用户要**存**东西 → 知识入库
- 用户要 AI **出去搜**新信息 → 网络调研
- 用户要**问库里已有的**知识 → 本 skill
- 问题超出库内知识时，明确告知"库内没有，是否发起网络调研补充"，不擅自联网

---

## 工作流程

### 第一步：定位

- 读 `0_系统配置/INDEX.md`，从目录中定位相关页面（优先综合页，其次来源笔记）
- INDEX 不足以定位时，用 Grep/Glob 按关键词搜索全库

### 第二步：阅读

- 优先读 `5_Wiki/` 下的综合页——它们已是编译好的多源结论
- 需要细节或出处时，顺 Wiki Link 下钻到来源笔记
- 记录本次答案实际依据了哪些页面

### 第三步：作答

- 回答必须**带引用**：关键结论后标注 `（[[页面名]]）`
- 综合页已标注的「⚔️ 矛盾与张力」必须如实呈现，不替用户抹平分歧
- 库内证据不足的部分，明确说"库内暂无此信息"，绝不编造
- 答案形式随问题而变：对比表、时间线、结构化分析、简答均可

### 第四步：回灌询问

答案有沉淀价值时（跨 ≥ 3 个来源的综合、新的对比分析、用户追问多轮的主题），主动问一句：

> 这个答案要不要存为综合页？存入后下次直接可查，也会随新来源持续更新。

用户同意后：

- 按综合页标准格式（`type: qa`）写入 `5_Wiki/问答页/`
- 更新 `0_系统配置/INDEX.md` 登记新页
- 追加 `0_系统配置/LOG.md`：`## [YYYY-MM-DD] query | 问题摘要 → 已回灌/未回灌`

简单事实性问答（一句话答完的）不提议回灌，避免制造噪音页面。

---

## 注意事项

- 引用是硬要求：无法溯源的回答等于没有回答
- 呈现矛盾，不裁决矛盾——除非用户要求 AI 给出倾向性判断
- 回灌永远先问后写，答案页归入 `5_Wiki/问答页/` 而不是 Inbox（它是编译产物，不是原始来源）
- 即使未回灌，LOG.md 也记录本次问答（记录"问了什么"帮助未来的 lint 发现知识缺口）
