# 知识编译

> 本知识库的核心引擎。让知识从"被归档的笔记"升级为"持续复利的综合层"。
> 一篇新来源进来，不只是存好，而是让全库已有的结论变得更强——或者被推翻。
> 借鉴 Karpathy《LLM Wiki》模式：wiki 是 compounding artifact（复利型资产），编译一次，持续保鲜。
> 2026-08-18 生命周期升级（借鉴《LLM Wiki v2》）：知识有生老病死——事实带置信度、被推翻的结论入墓碑、重复的做法凝成方法页、项目完结蒸馏结晶。

---

## 触发条件

- 「知识入库」或「网络调研」完成并经用户确认后，自动触发一次编译
- 用户说："编译一下""更新综合页""把这篇编译进去"
- 用户说："这篇和哪些相关""找关联""帮我连接"（原「知识关联」触发词，由本 skill 承接）
- 用户请求全库编译："全库编译""重建综合层"
- **项目结项**：项目 frontmatter `status` 改为 `done`，或用户说"结项结晶""项目复盘"（走下方「结项结晶」流程）
- 用户手动 `/编译`

## 综合层结构（5_Wiki/）

| 子目录 | 页面类型 | 示例 |
|--------|----------|------|
| `5_Wiki/实体页/` | 公司、人物、产品、工具 | 《埃森哲》《Claude Code》 |
| `5_Wiki/概念页/` | 方法论、概念、框架 | 《FDE模式》《PARA方法》 |
| `5_Wiki/论点页/` | 有争议的、正在演化的论点 | 《AI对IT服务外包的冲击》 |
| `5_Wiki/问答页/` | 由「知识问答」回灌的有价值问答 | 《为什么FDE比传统外包毛利高》 |
| `5_Wiki/方法页/` | 从重复做法提炼的可复用流程（程序性记忆） | 《售前PPT三步流水线》 |

综合页与普通笔记的本质区别：**普通笔记记录单一来源说了什么；综合页记录多个来源加起来意味着什么。**

四类页对应记忆的分层：来源笔记≈情景记忆，实体/概念/论点页≈语义记忆，**方法页≈程序性记忆**——同一做法在 ≥2 个来源或项目中出现，即提炼成页。

### 综合页标准格式

```markdown
---
type: entity | concept | thesis | qa | method
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: N
tags: [xxx, yyy]
---

# 页面标题

## 当前综合结论
（3-8 句，代表截至最近一次编译的最新理解）

## 关键事实与观点
- 事实 A（来源：[[某笔记]]，YYYY-MM-DD｜1 源）
- 事实 B（来源：[[某笔记]]、[[另一笔记]]，YYYY-MM-DD｜2 源加固至 MM-DD）
- 事实 C（来源：[[某笔记]]，YYYY-MM-DD｜有争议，见 ⚔️）

## ⚔️ 矛盾与张力
- [[来源A]] 认为 X，但 [[来源B]]（更新）认为非X —— 状态：未解决 / 已裁决→墓碑 / 已由新证据解决
（无矛盾时保留小节，写"暂无"）

## 🪦 墓碑（被替代结论）
（被裁决推翻的旧结论埋葬于此：保留原文 + 替代者 + 日期 + 原因；无时写"暂无"）
- 旧结论 X —— 被 [[新证据]] 替代（YYYY-MM-DD）：一句话原因

## 演化日志
- YYYY-MM-DD：因 [[新来源]] 加入，修订了关于XX的结论
```

**置信度尾标**是本库的置信度表达方式：不用浮点伪精确，用「源数 × 加固时间 × 争议状态」三元组，人可读、体检可算。规则：

- 单源新事实：`｜1 源`
- 新证据追加后**就地升级**旧条目尾标：`｜N 源加固至 MM-DD`
- 卷入未裁决矛盾：`｜有争议，见 ⚔️`
- 墓碑中已替代的结论不再标尾标（已出局）

### 方法页标准格式（type: method）

```markdown
---
（frontmatter 同上，type: method）
---

# 方法名

## 适用场景
（什么信号出现时该用这个方法）

## 步骤
1. …（可复现的操作序列，写清每步产出什么）

## 已验证案例
- [[项目或笔记]]：效果/量化结果（案例是方法的证据，≥2 个才立得住）

## 失败与边界
（什么情况下不适用、踩过的坑）

## 演化日志
```

## 工作流程

### 第一步：确定编译范围

- 默认：刚入库/刚调研完成的笔记
- 用户指定：某篇笔记、某个目录、或"全库编译"
- 全库编译前先告知预估工作量，等用户确认

### 第二步：识别触及的综合页

通读新笔记，回答四个问题：

1. **它提到了哪些已有综合页？**（读 `0_系统配置/INDEX.md` 的 5_Wiki 部分定位）
2. **它是否推翻、削弱或强化了某个综合页的现有结论？**
3. **它是否值得新建综合页？**（判断标准：该实体/概念/论点已被 ≥ 2 个来源触及，或用户明确关注）
4. **它是否是某个做法的又一次重复出现？**（同一做法在 ≥2 个来源/项目中出现 → 提炼或更新方法页）

一篇有信息量的来源，通常会触及 3-10 个综合页。

### 第三步：执行编译

对每个触及的综合页，五种动作：

- **强化**：新证据支持现有结论 → 在「关键事实与观点」追加条目（带置信度尾标）；若旧条目因此从单源变多源，就地升级其尾标（`1 源` → `N 源加固至 MM-DD`）
- **矛盾**：新证据与现有结论冲突 → **绝不静默覆盖**。在「⚔️ 矛盾与张力」显式记录双方及出处，相关事实尾标改 `有争议`，等积累更多证据或用户裁决后才改写「当前综合结论」
- **裁决**：用户明确裁决（如"矛盾第 2 条按新来源裁决"）→ 旧结论**原文移入「🪦 墓碑」**（注明替代者、日期、原因），然后改写「当前综合结论」，矛盾状态改 `已裁决→墓碑`。被替代 ≠ 被删除
- **修订**：证据足以改变结论 → 改写「当前综合结论」，并在「演化日志」记一笔为什么改
- **新建**：需要新页 → 按标准格式创建，向用户提议一句

同时铺设**类型化**双向链接（原「知识关联」职责）：

- 关系词表固定六种：`支撑` / `反驳` / `依赖` / `导致` / `同属` / `演化为`
- 综合页 ↔ 来源笔记：编译时天然形成（事实行的来源标注）
- 来源笔记 ↔ 来源笔记 / 来源笔记 ↔ 综合页：在**结构化笔记**末尾「相关笔记」小节追加，格式统一为：
  `- [[B]] ─关系→ [[C]]｜一句话关联原因`（B、C 为关系两端，书写时以语义自然方向排列，来源笔记中用"本篇"占位）
  例：`本篇 ─支撑→ [[FDE]]｜为"需求调研顾问"侧面提供操作证据`
- 已存在的关联不重复添加；单篇笔记关联数 ≤ 5 对；置信度低时标注 `<!-- 关联原因：待确认 -->`

### 第四步：更新索引与日志（铁律）

- 更新 `0_系统配置/INDEX.md`：新建的综合页登记一行（链接 + 一句话摘要 + 来源数）；被修订的综合页更新摘要
- 追加 `0_系统配置/LOG.md`：`## [YYYY-MM-DD] compile | 来源标题 → 触及 N 页（新建 X，修订 Y，矛盾 Z，裁决 W）`

### 第五步：输出编译报告

```
🔨 编译报告 — 《来源标题》

触及综合页：N 个
| 综合页 | 动作 | 说明 |
|--------|------|------|
| [[埃森哲]] | 修订 | 组织架构调整信息更新了"当前综合结论" |
| [[FDE模式]] | 强化 | 新增 1 条支持性证据，尾标升级 2 源加固至 08-14 |
| [[AI对外包的冲击]] | ⚔️ 矛盾 | 新来源与 6 月综述结论冲突，已标注待裁决 |
| [[旧结论]] | 🪦 裁决 | 按用户裁决移入墓碑，被 [[新证据]] 替代 |

新建综合页：《XXX》（已征求意见）
新增类型化关联：N 对
INDEX.md / LOG.md 已更新 ✓
```

## 结项结晶（crystallization）

项目完结不只是交付物归档——**探索过程本身就是知识来源**，和一篇外部文章同等对待：问题、做法、发现、教训都值得入库，否则项目一结，素材全成孤岛。

触发：项目 `status` → `done`，或用户说"结项结晶""项目复盘"。

流程：

1. **通读项目目录**全部笔记与交付物，回答四问：当初要解决的问题是什么？实际怎么做的（与计划的偏差）？发现了什么（含推翻预期的发现）？教训是什么？
2. **蒸馏一页**：有可复用做法 → 建方法页（优先）；有仍在演化的判断 → 建论点页；纯过程复盘 → 论点页并挂项目 Wiki Link
3. **素材归位**：项目内孤立笔记挂上类型化关系链（通常 `─支撑→` 结晶页），消灭"项目孤岛"
4. 更新 `0_系统配置/INDEX.md`，追加 `0_系统配置/LOG.md`：`## [YYYY-MM-DD] compile | 结项结晶：项目名 → 蒸馏 [[页面]]，关联素材 N 篇`

## 注意事项

- 综合页由 AI 全权维护，用户只读不写；来源笔记的**正文绝不修改**，只允许在**结构化笔记**末尾追加「相关笔记」小节——**`0_Inbox/raw/` 的存证原文永不追加、永不修改任何内容**（2026-07-02 编译器曾越权把"相关综合页"节写进 raw，reset 后留下 3 个死链——此为最严重违规，严禁重演）
- 矛盾处理是本 skill 的灵魂：**记录矛盾比消除矛盾更有价值**，静默覆盖旧结论是最严重的违规；即使裁决也必须走墓碑留痕
- 每条结论必须可溯源（Wiki Link 到来源笔记），无出处的结论不写入综合页；置信度尾标随每次编译维护，反映加固/争议状态
- 新建综合页宁缺毋滥：单一来源提到的边缘实体不建页，等第二个来源出现（方法页同理：≥2 次实践才立页）
- 全库编译可能耗时较长，先告知用户"正在编译..."
