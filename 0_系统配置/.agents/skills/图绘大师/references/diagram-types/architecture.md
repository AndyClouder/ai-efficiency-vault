# 类型：architecture(分层架构 / 系统架构)

> 3-5 层水平堆叠，每层并列多个节点。用于系统/软件的分层总览：谁在上层、谁在下层、跨层依赖。

## 1. 构图骨架

```
┌─────────────────────────────────────────────┐
│  应用层 · APPLICATION                        │  ← 层容器(半透明底+虚线框+层标题)
│   [节点A]  [节点B]  [节点C]  [节点D]          │
├─────────────────────────────────────────────┤
│  服务层 · SERVICE                            │
│   [节点E]  [节点F]  [节点G]  [节点H]          │
├─────────────────────────────────────────────┤
│  数据层 · DATA                               │
│   [节点I]            [节点J]                 │
└─────────────────────────────────────────────┘
              [基础层 · 跨切关注点横条]
```

- **层容器**：每层一个半透明矩形 + 虚线描边 + 左上角层标题(层名 + 编号 01/02/03)
- **节点**：每层 2-5 个卡片，同层等宽等高，水平排列
- **层间关系**：默认上层依赖下层，**通常不画跨层箭头**(分层图重在结构，非调用关系)；若必须表达调用，画 1-2 条纵向箭头点到为止
- **基础层**：底部一条横向窄条，放跨切关注点(日志/监控/配置/安全)，用小药丸标签

## 2. 节点规则

| 字段 | 内容 | 字号 |
|---|---|---|
| 字母图标 | 首字母(如 W=Web) | 16px |
| 标题 | 中文名(≤6 字) | 15px |
| 副标题 | 英文/类型 | 12px |
| 说明 | 一行简述(≤16 字) | 11px |

每层用不同主色系区分(应用层蓝、服务层紫、数据层绿)，但都在 spec_lock 配色范围内。

## 3. 默认画布

1280×720(16:9)。3 层最舒适；4-5 层时可改 1280×900 或缩小层间距。

## 4. 参考模板

`templates/charts/layered_architecture.svg` —— 3 层 + 右侧输出列 + 底部基础层，结构最完整。取其层容器 + 卡片 + 基础条的画法。

## 5. 红线

- ❌ 不要在分层图里画大量调用箭头(那是 sequence/component 的活)
- ❌ 同层节点不等宽不等高(破坏结构感)
- ✅ 层标题用"层名 · LAYER ENGLISH"双语，字距加宽(letter-spacing=1)
