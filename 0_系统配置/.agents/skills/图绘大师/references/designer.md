# 角色：图表设计师(Designer)

> 在内容解析(Step 3)与确认(Step 4)之间，辅助选定图类型与视觉规格。本技能采用轻量设计——设计师不单独成阶段，而是作为 Step 3-4 的辅助角色：当实体/关系/层级已提炼出来，设计师负责把它们映射到具体的图类型与构图方案。

---

## 1. 何时介入

设计师在以下时机被读取：

- Step 3 末尾：内容解析师给出"推荐图类型"后，若对选型不确定，读本文辅助决策。
- Step 4：起草视觉规格推荐(画布 / 配色 / 字体 / 图标)时。

> 默认流程下，内容解析师直接在 `analysis.md` §5 给出推荐，设计师是"想再核对一下选型对不对"时的参考。

## 2. 选型决策矩阵

按源材料的**主结构特征**选图(不是按"好不好看")：

| 主结构特征 | 首选类型 | 备选 | 反例(别用) |
|---|---|---|---|
| 明显分层(应用/服务/数据、抽象层) | `architecture` | `hierarchy` | 不要用 flowchart(没有流向) |
| 有先后顺序的步骤 | `flowchart` | `data-flow`(若侧重数据) | 不要用 mindmap(无序列) |
| 请求-响应、多角色交互 | `sequence` | `flowchart`(简化版) | 不要用 architecture(不是分层) |
| 围绕一个中心概念展开 | `framework` | `mindmap`(若发散多于结构) | 不要用 flowchart |
| 发散性知识/读书笔记 | `mindmap` | `hierarchy` | 不要用 matrix |
| 模块间依赖关系 | `component` | `architecture` | 不要用 sequence |
| 数据从一处流向多处 | `data-flow` | `flowchart` | 不要用 cycle |
| 树状组织/分类 | `hierarchy` | `mindmap` | 不要用 architecture(除非分层) |
| 2×2 象限分析(SWOT/BCG) | `matrix` | — | 不要用 flowchart |
| 闭环改进(PDCA/飞轮) | `cycle` | `flowchart`(带回环) | 不要用 timeline |
| 历史演进/路线图 | `timeline` | `flowchart`(若步骤=时间) | 不要用 cycle |
| 前后/优劣对比 | `comparison` | `matrix`(2×2) | 不要用 hierarchy |

**多图拆分原则**：源材料若同时含"分层结构"和"请求链路"，拆成两张(architecture + sequence)，而不是硬塞进一张。

## 3. 视觉规格推荐(供 Step 4 起草)

### 3.1 画布

| 场景 | 画布 | 说明 |
|---|---|---|
| 默认 | `1280×720` | 16:9，适配屏幕/PPT/网页 |
| 纵向长流程(>6 步) | `720×1280` | 竖版，避免横向拥挤 |
| 宽幅流程/时间线 | `1920×720` | 横长条，适合横向多节点 |
| 方形(中心辐射/矩阵) | `1080×1080` | 1:1，社交/文档嵌入友好 |

### 3.2 配色方案(3 套预设，按内容气质选)

**A. 科技深蓝(默认，技术架构)**

| 角色 | HEX | 用途 |
|---|---|---|
| 主色 | `#1E3A5F` | 主要节点/标题 |
| 次主色 | `#3B82F6` | 次级节点/链接 |
| 底色 | `#F8FAFC` | 画布背景 |
| 卡片底 | `#FFFFFF` | 节点卡片 |
| 强调 | `#D4AF37` | 焦点/高亮(<5%面积) |
| 正文 | `#0F172A` | 文字 |
| 辅助文字 | `#64748B` | 说明/副标题 |

**B. 商务暖灰(管理/组织类)**

| 角色 | HEX |
|---|---|
| 主色 | `#1F2937` |
| 次主色 | `#6366F1` |
| 底色 | `#FAFAF9` |
| 强调 | `#DC2626` |
| 正文 | `#111827` |

**C. 清新绿青(生态/流程类)**

| 角色 | HEX |
|---|---|
| 主色 | `#065F46` |
| 次主色 | `#10B981` |
| 底色 | `#F0FDF4` |
| 强调 | `#F59E0B` |
| 正文 | `#064E3B` |

> 用户在 Step 4 可指定任意 HEX 覆盖；也可给"品牌色 / 麦肯锡蓝 / Notion 灰"等模糊描述，由你转成具体 HEX。

### 3.3 字体

统一字体栈(中英文混排友好)：
```
-apple-system, BlinkMacSystemFont, 'Segoe UI', 'Microsoft YaHei', 'PingFang SC', sans-serif
```

字号梯度(锚定正文 16px)：

| 角色 | 字号 | 字重 |
|---|---|---|
| 主标题 | 32px | 800 |
| 副标题/层标题 | 18-22px | 700 |
| 节点标题 | 16-18px | 700 |
| 正文/节点说明 | 13-14px | 400-600 |
| 标注/协议 | 11-12px | 400-600 |

### 3.4 图标

默认用**字母占位图标**(节点左上角圆角小方块 + 首字母大写)，与 ppt-master 的 `layered_architecture.svg` 一致。理由：

- 无需外部图标库依赖
- 跨平台渲染稳定
- 颜色可控(随主色/次主色)

用户若要"真图标"，引导其在导出后用 SVG 编辑器替换，或改用 emoji(但 emoji 跨平台渲染不稳，谨慎)。

## 4. 红线

- ❌ 不为追求美观牺牲结构准确性(流程别硬转成思维导图)
- ❌ 不在一张图里塞超过 2 种主结构(分层 + 流程应拆两张)
- ❌ 配色不超过 3 个主色 + 1 个强调色(太多颜色 = 信息噪音)
- ✅ 选型有理由，规格可追溯
